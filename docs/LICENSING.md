# Licensing decision before public release

No license has been selected or applied on the repository owner's behalf. This package is prepared for collaborative development, but it should not yet be described as an approved open-source release.

Before public release, the authorized owner should confirm ownership of the inherited HTML and new modifications, then choose an appropriate code license and add its actual text in a root-level LICENSE file. A permissive code license such as MIT may be considered, but adoption is an organizational decision. Public repository visibility alone should not be presented as permission for unrestricted reuse outside the platform's terms.

Choose a separate policy for original catalog descriptions and other project-authored documentation where needed. Third-party resources linked from the catalog retain their original rights and restrictions. A code license must not be described as licensing the linked research papers, syllabi, datasets, or tools.

Reference: GitHub Docs, Licensing a repository, linked in `TECHNICAL_REFERENCES.md`.
